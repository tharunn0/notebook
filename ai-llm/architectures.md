# Neural Network Architectures: Key Concepts & Mechanics

A foundational guide covering the major neural network architectures—convolutional, recurrent, and attention-based—and the structural biases that make each suited to its domain.

---

## What is a Convolutional Neural Network (CNN), and why does it suit image data?

A Convolutional Neural Network is a neural architecture that replaces the fully-connected layer's dense, unconstrained weight matrix with small, learned filters (kernels) that slide across the input and share the same weights at every spatial position, exploiting the fact that visual patterns—edges, textures, shapes—are local and translation-invariant: a filter that detects a vertical edge in the top-left of an image should detect the same edge anywhere else in the image using the identical weights.

Mechanically, a convolutional layer applies a small filter (e.g., 3x3 or 5x5) across the input by computing a dot product between the filter's weights and each local receptive field it slides over, producing a feature map where each output position summarizes a small local neighborhood of the input. Stacking convolutional layers grows the effective receptive field, so early layers detect low-level features like edges and color gradients while deeper layers combine these into increasingly abstract, composite features (textures, object parts, whole objects). Pooling layers (max or average pooling) periodically downsample feature maps, reducing spatial resolution and parameter count while adding a degree of local translation invariance—a feature detected slightly shifted in position still activates the same downstream pooled unit. Because a filter's weights are shared across every spatial location, a CNN needs vastly fewer parameters than a fully-connected layer processing the same input, and this weight-sharing is precisely the inductive bias—locality plus translation equivariance—that lets CNNs learn efficiently from image data with far less training data than an unconstrained dense network would require.

Production CNN architectures layer additional structural refinements on this base: residual connections (ResNet) let gradients skip across blocks to train very deep networks without vanishing gradients, batch normalization stabilizes activation statistics layer to layer, and depthwise-separable convolutions (MobileNet) factor a standard convolution into cheaper operations for edge/mobile deployment. The trade-off is that CNNs' strong locality bias, which is an asset for natural images, becomes a limitation for tasks requiring long-range or global context—which is a major reason vision transformers (ViTs), which apply attention across image patches instead of local convolutions, have become competitive with or superior to CNNs on large-scale image tasks where enough training data is available to learn spatial relationships without a hand-built locality prior.

## What is a Recurrent Neural Network (RNN), and what problem do LSTMs/GRUs solve for it?

A Recurrent Neural Network is a neural architecture designed for sequential data that maintains a hidden state vector carried forward across time steps, processing one element of a sequence at a time and updating that hidden state as a function of the current input and the previous hidden state—giving the network a form of memory that lets earlier elements of a sequence influence how later elements are interpreted.

Mechanically, at each time step `t`, a vanilla RNN computes `h_t = activation(W_h · h_{t-1} + W_x · x_t + b)`, reusing the same weight matrices at every step, and the final or per-step hidden states are used for prediction. Training is done via backpropagation through time (BPTT), which unrolls the recurrence across all time steps and applies the chain rule backward through that unrolled graph exactly as in a deep feedforward network—except here, "depth" equals sequence length, and the same weight matrix is multiplied repeatedly at every step. This repeated multiplication is the vanilla RNN's fatal flaw: gradients shrink toward zero (vanishing) or blow up (exploding) exponentially with sequence length, meaning a vanilla RNN in practice cannot learn dependencies spanning more than roughly a dozen time steps, regardless of how important a distant token might be to the current prediction.

LSTMs (Long Short-Term Memory) and GRUs (Gated Recurrent Units) solve this by introducing gating mechanisms that let the network learn to preserve information across long spans rather than being forced to repeatedly transform it. An LSTM maintains a separate cell state alongside the hidden state, and uses learned forget, input, and output gates—each a sigmoid-activated vector between 0 and 1—to control how much of the previous cell state to retain, how much new information to write in, and how much of the cell state to expose as output; because the cell state update is largely additive (gated addition rather than repeated matrix multiplication), gradients can flow across many time steps with far less decay. GRUs simplify this with two gates (reset and update) and no separate cell state, trading a small amount of expressiveness for fewer parameters and faster training, and often matching LSTM performance on many tasks. In production, both architectures have been substantially displaced for sequence modeling by transformer/attention-based architectures, which process a sequence in parallel rather than step by step and access any position directly rather than through a bottlenecked hidden state—but RNN variants remain relevant for streaming/low-latency inference and resource-constrained settings where a transformer's quadratic attention cost or full-sequence buffering is impractical.

## What is the attention mechanism, and how does self-attention differ from RNN-style sequence modeling?

Attention is a mechanism that lets a model compute, for each element of a sequence, a weighted combination of all other elements' representations, with the weights learned dynamically based on how relevant each other element is to the current one—replacing an RNN's single bottlenecked hidden state with direct, content-based access to every position in the sequence.

Mechanically, self-attention projects each input token's embedding into three vectors—a Query, a Key, and a Value—via learned weight matrices. For a given token, its Query vector is dot-producted against every other token's Key vector to produce a raw compatibility score, these scores are scaled (divided by the square root of the key dimension, to keep gradients well-behaved) and passed through a softmax to produce attention weights that sum to 1, and the token's output representation is then the weighted sum of every token's Value vector using those weights. Because every token attends to every other token in a single matrix-multiplication-driven operation, this can be computed in parallel across the whole sequence rather than sequentially, and the "path length" between any two tokens—no matter how far apart—is exactly one attention hop, versus the many sequential steps a signal must survive in an RNN's hidden state. This is precisely what solves the long-range dependency problem structurally rather than through gating: there is no repeated multiplication for a distant token's influence to vanish through.

The trade-off is computational: self-attention's cost scales quadratically with sequence length (every token compares against every other token), whereas an RNN's cost scales linearly, which is why long-context transformer inference and training are dominated by attention cost and have driven substantial research into sub-quadratic approximations (sparse attention, linear attention, sliding-window attention) and efficient exact-attention kernels (FlashAttention) that reduce memory traffic without changing the mathematical result. In production LLMs, self-attention is used in its "masked" (causal) form during autoregressive generation—each token may only attend to itself and earlier tokens, enforced via a triangular mask on the attention scores—so that the model cannot see future tokens it is meant to predict, and multi-head attention runs several independent attention computations in parallel subspaces so different heads can specialize in different relationship types (e.g., syntactic dependency versus coreference) before their outputs are concatenated and projected back to the model's dimension.

## What is a Transformer architecture, and what are its core components?

A Transformer is a neural architecture built entirely from stacked self-attention and feed-forward layers, with no recurrence or convolution, that processes an entire sequence in parallel while still modeling dependencies between arbitrarily distant tokens—it is the architecture underlying essentially all modern large language models, as well as most state-of-the-art vision and multimodal models.

A Transformer block is composed of a few core components applied in sequence, each wrapped in a residual connection and layer normalization to keep gradients well-behaved through deep stacks: multi-head self-attention, which lets every token gather context from every other token as described above; a position-wise feed-forward network, a small two-layer MLP applied independently and identically to every token position, which gives the model additional per-token representational capacity beyond what attention's weighted-averaging provides; and positional encoding, which is necessary because self-attention itself is permutation-invariant—it has no inherent notion of token order—so a positional signal (either fixed sinusoidal encodings added to the input embeddings, or, in most modern LLMs, relative schemes like Rotary Position Embeddings (RoPE) applied directly inside the attention computation) must be injected explicitly to give the model any sense of sequence order. The original Transformer used a full encoder-decoder structure (an encoder that processes the input bidirectionally, and a decoder that generates output autoregressively while cross-attending to the encoder's representations), which remains standard for sequence-to-sequence tasks like translation, but most modern LLMs (GPT-family, Llama, Claude) use a decoder-only variant: a single stack of causally-masked self-attention and feed-forward blocks trained purely as a next-token predictor.

Architecturally, decoder-only models dominate because next-token prediction over massive unlabeled text corpora is a training objective that scales cleanly with data and compute and produces a single unified architecture usable for essentially any downstream language task via prompting or fine-tuning, rather than requiring task-specific encoder-decoder setups. Senior engineers reason about Transformer deployment costs in two distinct regimes: training/prefill, where attention's quadratic cost and the feed-forward blocks' matrix multiplications dominate and are highly parallelizable across the full input; and autoregressive decoding, where each new token requires a fresh forward pass and Key/Value vectors from all previous tokens must be cached (the "KV cache") to avoid recomputing them, making decode-time inference primarily memory-bandwidth bound rather than compute bound—a distinction that drives most of the practical work in LLM inference optimization (quantization, KV-cache compression, speculative decoding, and batching strategies).
